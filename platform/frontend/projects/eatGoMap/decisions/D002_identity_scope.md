# 初期使用者識別範圍

## Decision

- 定義兩人私人使用階段的身分範圍與延後項目。

## Status

- accepted

## Context

- 專案初期只有兩位已知成員使用。
- 使用者已確認冒用身分目前不是問題，正式身分機制可待專案擴充時再設計。

## Options Considered

- 選項 A：第一版即建立帳密、Token、角色與權限。
- 選項 B：第一版採固定身分選擇與本機記憶，保留日後替換邊界。
- 選項 C：所有資料不記錄使用者。

## Chosen Direction

- 採用選項 B。
- 初期只需要辨識兩位使用者，不將防冒用視為第一階段完成條件。

## Impact

- 對架構的影響：使用者身分仍應由集中能力提供，避免頁面各自判斷。
- 對實作的影響：未來可替換為正式登入，但現階段不因此阻擋地圖、收藏與打卡。
- 對後續文件的影響：API 契約仍須定義使用者識別欄位，但驗證機制標示為待後續決定。

## 現行實作

- 首次進入或此瀏覽器沒有有效選擇時，顯示全頁使用者選擇。選擇男生或女生後才載入地圖及收藏。
- `map-home` 透過 Container 取得會員 Store。Store 使用平台持久化機制，將本機識別值存於 `eatGoMap:member`。搜尋欄旁的頭像反映目前選擇，點擊可切換或取消。
- 會員識別值 `male` 與 `female` 只供目前前端使用。收藏仍共用原有資料流。

## Follow-up

- 在 API 契約階段確認初期使用者 ID 的允許值與傳遞方式。
- 使用者數量或公開範圍擴大前，重新評估驗證與權限。
