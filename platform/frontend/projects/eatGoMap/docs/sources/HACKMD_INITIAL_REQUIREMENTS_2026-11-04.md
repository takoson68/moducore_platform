# 美食 × 旅行打卡地圖＋旅遊日誌：初步需求探索

## 文件資訊

- 討論日期：2026 年 11 月 3 日晚間
- 文件階段：初步需求探索
- 專案成員：前端開發者、後端開發者
- 文件目的：彙整目前對功能與畫面的初步想像，作為前後端後續討論及完善規格的共同基礎。
- 備註：本文件記錄目前討論結果，尚未定案的內容將於後續討論中持續補充與調整。

## 一、專案概述

本專案為「美食 × 旅行打卡地圖＋旅遊日誌」，主要分為兩大功能：

1. 地圖區
2. 旅遊日誌區

整體將採類 App 的形式呈現，希望可透過 WebView 在手機上使用，並可在手機頁面上建立一個類似 App 的功能入口；具體實作方式尚待確認。

## 二、前後端分工與系統架構

### 2.1 前端

- 前端由前端開發者負責。
- 預計使用 Vue 與 Node.js。
- 前端開發者已有一個可供前端使用的免費伺服器。

### 2.2 後端

- 後端由後端開發者負責。
- 主要使用 PHP，但實際採用的架構尚在評估中。
- 後端的主要職責包含：
  - 資料庫處理。
  - 提供前端所需的 API。
- 後端需要尋找一個符合以下條件的免費伺服器：
  - 支援 PHP。
  - 最好能以自動部署的方式部署至遠端。此前端開發者強力建議採用自動部署。

### 2.3 初步部署規劃

- 目前初步規劃可能分為兩個伺服器：
  - 一個前端伺服器。
  - 一個後端伺服器。

## 三、地圖區

### 3.1 地圖初始畫面與搜尋範圍

- 地圖的呈現方式預期類似 Google Maps。
- 進入地圖畫面時，先定位使用者目前所在位置。
- 使用者可設定搜尋半徑，以目前位置為中心，顯示指定距離範圍內的店家或地點。
- 搜尋條件可包含評分，例如搜尋目前位置方圓 1 公里內、評分 3 至 5 星的店家。

### 3.2 地圖分類

- 地圖區上方設有兩個分類選項（checkbox）：
  - 美食
  - 旅遊
- 一般使用情境下，「美食」為預設選項。
- 選擇「美食」時，地圖搜尋結果只顯示餐廳類店家。
- 選擇「旅遊」時，考量旅遊通常包含景點與美食，地圖會顯示設定範圍內的景點與美食搜尋結果。

### 3.3 店家或地點資訊

- 點選地圖上的店家或地點 icon 後，顯示該地點的資訊框。
- 資訊框中的外部地圖資訊預計向 Google Maps API 取得，例如：
  - 店家或地點名稱。
  - 地址。
  - 電話。
  - 評分。
  - 座標。
- 除了 Google 提供的資訊外，系統另提供自行建立的個人紀錄功能：
  - 個人評分。
  - 評論（comment）。
  - 照片上傳。
  - 打卡。

### 3.4 新增與儲存店家或地點

新增店家或地點初步規劃有兩種方式：

1. 輸入地址，搜尋店家或地點。
2. 先透過 GET 取得 Google Maps 中、指定距離範圍內的店家或地點。

透過地圖搜尋新增資料時，初步流程如下：

1. 點選地圖上的店家 icon 或座標點。
2. 顯示店家或地點資訊框。
3. 資訊框中提供「儲存店家資訊」的 checkbox。
4. 勾選後，可先快速將店家或地點的基本資訊存入後端。
5. 此階段僅儲存基本資訊，尚不包含個人評分、評論等內容。
6. 下次進入地圖時，畫面除了顯示指定範圍內的潛在店家或地點，也會顯示先前已存入的店家或地點。
7. 使用者可再針對已存入的店家或地點進行打卡，並輸入或編輯評分、評論、照片等內容後存入資料庫。

### 3.5 照片儲存

- 資料庫僅記錄照片路徑，不直接存放照片實體資料。
- 專案成員上傳的照片將存放於一個雲端共用儲存空間或資料夾。
- 照片檔名可標註上傳者，以辨識照片由誰上傳。
- 讀取照片時，依資料庫記錄的路徑，從雲端共用資料夾取得照片。

## 四、旅遊日誌區

### 4.1 功能定位

- 旅遊日誌是將地圖區已存入的資料進行組合後輸出。
- 日誌區設有兩個分類選項（checkbox）：
  - 美食
  - 旅遊

### 4.2 旅遊日誌列表

- 選擇「旅遊」後，先顯示旅遊列表。
- 旅遊列表依旅遊時間由新到舊排序。
- 旅遊項目需支援新增與編輯。
- 每筆旅遊項目的主要資料包含：
  - 標題，例如：「8/1～8/6 日本大阪行」。
  - 日期區間。
- 系統可依旅遊項目的日期區間，搜尋該段時間內的景點與美食打卡紀錄。

### 4.3 旅遊足跡地圖

- 點選某一旅遊標題後，進入該次旅遊的足跡地圖。
- 地圖顯示該日期區間內，從第一天到最後一天的所有打卡點。
- 各打卡點以線條依順序串接。
- 起點、終點與路線使用顏色變化協助辨識行程方向，例如：
  - 起點及起始線條由紅色開始。
  - 終點及結束線條以紫色結束。
- 點選任一打卡點後，顯示該景點或餐廳的資訊框，內容包含：
  - Google 地圖相關資訊。
  - 個人評分。
  - 評論（comment）。
  - 照片。

### 4.4 美食日誌列表

- 選擇「美食」後，進入預設的美食列表。
- 列表依日期由新到舊排序，例如：
  - 11/3　XX 餐廳
  - 10/25　XX 餐廳
- 點選某一天的紀錄後，可查看當天打卡的店家資訊，包含：
  - 店家資訊。
  - 個人評分。
  - 評論（comment）。
  - 照片。

## 五、使用者識別與登入

- 前端將製作一個簡單的登入流程，主要提供使用上的儀式感及使用者識別。
- 第一次進入功能時，畫面會顯示兩位專案成員各自的圖像 icon。
- 使用者選擇自己的 icon 後，前端會記錄目前由誰使用。
- 下次進入時，不再顯示使用者選擇畫面，直接進入地圖。
- 若系統更版，將重新進行登入／使用者識別紀錄。

## 六、前後端資料傳遞待討論事項

- 美食或旅遊的分類資訊，可考慮由 request header 帶入，或由 request body 帶入。
- 實際採用方式尚待前後端進一步討論。

## 七、開發順序

功能開發順序初步規劃如下：

1. 優先開發地圖區功能。
2. 地圖區完成後，再進行旅遊日誌區功能。

1. 先將本次討論想法整理為初版規格。
