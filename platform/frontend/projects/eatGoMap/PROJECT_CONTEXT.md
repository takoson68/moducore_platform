# 食旅共享地圖與日誌 Context

---

## 0. 文件用途

本文件定義 `eatGoMap` 的背景、目標、範圍、限制與假設，並作為本專案背景理解的唯一主文件。

## 1. 專案目標

- 主要目標：讓兩位專案成員共同收藏美食與旅遊地點、建立各自的打卡紀錄，並整理成可回顧的共享日誌。
- 次要目標：以手機優先、接近 App 的使用體驗呈現地圖探索與旅遊足跡。
- 不做什麼：第一階段不建立複雜會員、角色權限、公開社群、導航服務或完整 App 商店上架流程。

## 2. 成功條件

- 使用者可從地圖搜尋或探索地點，辨識外部搜尋結果、已收藏與已打卡狀態。
- 使用者可為地點建立包含評分、評論、時間與照片的個人打卡紀錄。
- 使用者可建立旅程，選取或整理打卡紀錄並查看依順序串接的足跡。
- 前端與合作方後端以明確 API 契約交換資料，不直接耦合後端資料庫或 PHP 實作。

## 3. 使用者與場景

- 主要使用者：兩位共同開發並共同使用本專案的已知成員。
- 次要使用者：目前沒有；未來是否擴充多人使用另行決定。
- 核心使用場景：旅行前收藏地點、旅途中打卡與補充照片、旅行後依日期與足跡回顧美食及行程。

## 4. 商務範圍

- 涵蓋的業務領域：地點收藏、個人打卡、共同資料瀏覽、美食紀錄、旅程與旅遊日誌。
- 不涵蓋的業務領域：商家後台、廣告、交易、訂位、導航、公開社群與內容營利。
- 優先處理的商務需求：先完成地圖區及地點收藏／打卡流程，再處理旅遊日誌。

## 5. 功能範圍

- 必要功能：手機地圖、定位、地點搜尋、分類與距離篩選、共同收藏、地點資訊、個人打卡、評分、評論及照片關聯。
- 可延後功能：旅程建立、足跡地圖、美食日誌、旅遊日誌、PWA／WebView 包裝、正式身分驗證與多人權限。
- 明確排除功能：第一階段不做道路導航、即時位置共享、公開貼文、社交關係與跨 Project 帳號系統。

## 6. 非目標

- 本階段不處理：真實地圖 SDK、定位權限、API Client、後端程式、資料庫 Schema、部署與第三方服務申請。
- 本專案不承諾：目前的 UI 草稿即為最終視覺、目前需求已完成 API 合約，或合作方伺服器已具備正式上線條件。

## 7. 已知限制

- 人力限制：目前由一名前端開發者與一名後端開發者合作，產品使用者也是這兩位成員。
- 技術限制：前端與後端分開部署；跨來源請求需要 HTTPS、CORS 與環境設定配合。
- 時程限制：尚未定義正式里程碑與交付日期。

## 8. 外部依賴

- 外部系統：合作方維護的 PHP 後端與資料庫。
- 外部 API：合作方提供的 Project API；地圖與地點資料 API 尚待選定及定義。
- 第三方服務：Google Maps 或替代地圖服務、照片物件儲存或共用雲端空間。

## 9. 假設

- 初期僅供兩位已知成員私人使用，可先採輕量使用者識別，不將防冒用列為第一階段需求。
- ModuCore 的 Project／Module 邊界可支援後續增加正式登入、多使用者或替換 API 來源。
- 外部地點與自有收藏／打卡資料未來需以穩定的外部地點識別值合併與去重。
- 旅程足跡第一版可依打卡順序連線，不等同真實道路導航路線。
