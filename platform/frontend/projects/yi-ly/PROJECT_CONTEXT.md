# PROJECT_CONTEXT.md
## 易經解卦 Context

## 0. 文件用途

本文件定義 `yi-ly` 的背景、目標、範圍、限制與假設，並作為本專案背景理解的唯一主文件。

## 1. 專案目標

- 主要目標：提供以《周易》本卦、動爻、之卦及可追溯經文為核心的卜問工具，並讓一個卜問結構中的每個步驟各自取得一個完整卦象。
- 次要目標：讓使用者可明確選擇下載版本化經文資料並離線使用。
- 次要目標：輸出結構化卦象，第一版供使用者自行交給外部 AI。
- 不做什麼：不把龜卜、鳥卦、六壬、籤詩等不同占術冒充為《周易》六爻，也不提供無來源詩籤或沒有經文依據的必然斷語。

## 2. 成功條件

- 正確取得本卦、所有動爻與之卦。
- 每段卦辭、爻辭、傳文及本站導讀都能辨識層級與來源。
- 使用者同意下載後，可在完全斷網並重新載入時完成核心流程。
- 使用者不需會員即可使用；歷史只在明確選擇後保存於本機。
- 複製給外部 AI 的內容只包含本次使用者選擇分享的資料。

## 3. 使用者與場景

- 主要使用者：希望以繁體中文查閱《周易》並完成一次起卦的一般使用者。
- 次要使用者：未來可能需要檢查底本、授權、異文及導讀品質的內容審校者；不屬 MVP 角色。
- 核心場景：手機上提出問題、選擇卜問結構，依步驟完成一至多次獨立起卦，再查看整體結果並視需要複製給外部 AI。
- 身分模式：公開免登入，不建立會員與跨裝置同步。

## 4. 商務範圍

- 涵蓋：經文資料、來源追溯、金錢法起卦、單卦與多步驟卜問結構、結果閱讀、選配離線資料、本機歷史與外部 AI 交接。
- 不涵蓋：宗教背書、高風險決策、混合占術及現代出版社內容的未授權重製。
- 優先需求：經文正確性、手機操作、版本可追溯、離線可靠性與解讀邊界。

## 5. 功能範圍

- 必要功能：三錢起卦、手動輸入、單卦問事、逐步卦象結果、經文來源、簡明導讀、離線下載與刪除、結構化 AI Context。
- 必要功能：讓使用者選擇是否保存本機歷史；新紀錄預設名稱為 `TAKO` 且可修改。
- 可延後功能：三卦／五卦卜問結構、蓍草法、梅花易數、內容審校後台及具來源的多家解讀模式。
- 明確排除：第一版站內 AI、會員、雲端同步、AI 即興詩籤，以及尚未建立獨立規則與語料模型的龜卜、鳥卦、六壬、抽籤擲筊。

## 6. 非目標

- 本階段不實作業務頁面、Worker endpoint、D1 schema 或 AI 串接。
- 本專案不承諾預測必然未來，也不替使用者做高風險決策。
- 本階段不確定營利模式、內容管理角色或正式部署環境。

## 7. 已知限制

- 約 450 段現代簡明導讀需逐條編輯與審校。
- 古籍原文雖已進入公有領域，現代標點、編排、翻譯與註解可能具有獨立權利。
- 瀏覽器離線能力受儲存空間、使用者權限與清除網站資料影響。
- 外部 AI 不在本專案控制範圍內，複製內容需附帶明確解讀限制。

## 8. 外部依賴

- 外部系統：規劃由 ModuCore Cloudflare Worker 提供權威資料 Query；正式部署資源待確認。
- 外部 API：第一版核心流程不依賴第三方 API，也不串站內 AI。
- 第三方資料：可能使用維基文庫、Kanripo 或公有領域掃描本；正式底本與授權組合待裁決。

## 9. 假設

- `yi-ly` 是已確認的 Project 目錄名稱與 `tenant_id`。
- 顯示名稱已確認為「易經解卦」。
- MVP 公開免登入、手機優先。
- 第一版只提供複製給外部 AI。
- 卜卦歷史預設不保存；使用者選擇保存時，預設紀錄名稱為 `TAKO`。
