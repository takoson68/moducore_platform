# 卜法與卜問結構分類

## 1. 文件目的

本文件區分「用什麼方法得到結果」、「一次諮詢包含哪些步驟」及「同一結果採用哪一種閱讀視角或解讀資料」。三者可以同時存在，但不可混為同一個設定。

## 2. 三層產品模型

### 2.1 卜法 `DivinationMethod`

卜法決定如何產生一個結果，以及結果使用哪一套規則與語料。

### 2.2 卜問結構 `ConsultationLayout`

卜問結構定義一次諮詢有幾個有順序的步驟，以及每一步要回答的子問題。每個步驟都產生一個獨立結果，不能把同一個本卦、動爻、之卦拆成三個不同步驟。

### 2.3 結果解讀 `ResultInterpretation`

結果解讀是在單一步驟內呈現原始結果、可追溯文本、固定導讀及限制。對《周易》而言，一個完整結果包含本卦、全部動爻與之卦；資料足夠時，可在不改變卦象的前提下切換不同閱讀視角或具來源的解讀流派。

解讀資料必須標示 `interpretationId`、名稱、底本或作者／編者、適用卜法、版本、授權及審校狀態。經典原文、本站中性導讀、歷代／現代解讀與 AI 生成內容必須分層，不可互相冒充。

### 2.4 解讀資料候選

| 層級 | 內容 | 發布條件 |
|---|---|---|
| 經典原文 | 卦辭、爻辭及核准納入的《易傳》 | 固定底本、版本與異文紀錄 |
| 本站簡明導讀 | 字義、位置與中性語意整理 | 逐段人工審校，不針對個人情境下斷語 |
| 歷代注疏 | 例如王弼／孔穎達系統、程頤、朱熹等具名文本 | 確認版本、轉錄授權、段落對照及必要的白話導讀 |
| 本站主題解讀 | 針對關係、工作、決策等情境整理 | 每段可回溯經文依據，清楚標為本站編輯內容 |
| AI 情境解讀 | 使用者主動交給外部 AI 的當次回答 | 第一版不收錄為 corpus，也不得冒充固定流派 |

### 2.5 同一卦的選配閱讀方式

閱讀方式只決定如何從已取得的完整卦象中選出重點文字，不改變起卦、六爻、本卦或之卦。MVP 預設閱讀方式仍依 D006；以下兩種列為可選擴充：

- **朱熹《易學啟蒙・考變占》**：依動爻數選讀本卦、之卦的卦辭／爻辭。此為具名的傳統選讀規則，不是新的起卦方法，也不取代完整結果。
- **焦氏易林**：在適用的卦變閱讀流程中，以本卦及之卦定位相應林辭；它是獨立的古典占辭語料，不是《周易》卦爻辭或《易傳》，也不是本站自行撰寫的解釋。使用時須明示版本、配對方式及文本來源。

朱熹考變占的選讀表（動爻位置均按初爻至上爻計；完整結果仍照常顯示）：

| 動爻數 | 選讀內容 |
|---:|---|
| 0 | 本卦卦辭 |
| 1 | 本卦該動爻爻辭 |
| 2 | 本卦兩條動爻爻辭；以上爻為主 |
| 3 | 本卦與之卦卦辭；依原書卦例安排主次 |
| 4 | 之卦兩條不變爻爻辭；以下爻為主 |
| 5 | 之卦唯一不變爻爻辭 |
| 6 | 乾、坤分別讀用九、用六；其他卦讀之卦卦辭 |

二變、四變的選讀規則需標示為依卦例推演（原文有「經傳無文，今以例推之」的說明）；三變的本卦／之卦主次依具體卦例，不宜簡化成所有情況一律本卦為主。實作須以核對過的原文版本及例表為準。

《焦氏易林》依「本卦 → 之卦」取一條林辭；若收錄完整，總數為 4096 條，而非每個本卦只有一條。結果可展示該配對的一首四言林辭，另提供來源和原文脈絡。不得在缺少使用者選擇時把林辭自動混作《周易》原文或確定性預言。

同一結果頁可由使用者選擇是否展開這些閱讀方式。不同閱讀方式的文字並列且各自署名，不合併成 AI 式斷語；未提供某選項時仍完整呈現本卦、所有動爻及之卦。

「資料夠齊全」至少表示：涵蓋範圍可說明、缺文可辨識、段落映射可驗證、來源與授權可追溯、內容通過審校；不是只找到少量網路文章便以整套流派名義發布。

## 3. 卜法分類

| 類別 | 產生的結果 | 與《周易》六十四卦關係 | 產品處理 |
|---|---|---|---|
| 金錢卦／三錢法 | 六個 6／7／8／9 爻值 | 直接形成本卦、動爻、之卦 | MVP |
| 蓍草筮法 | 六個 6／7／8／9 爻值 | 直接形成本卦、動爻、之卦 | 後續方法，可共用易卦結果模型 |
| 梅花易數 | 依時間、數字或外應取得卦與動爻 | 使用八卦、六十四卦，但起卦與判讀規則不同 | 後續獨立引擎，不視為三錢法皮膚 |
| 六爻／納甲 | 六爻卦加干支、六親、世應、五行等 | 建立在六爻卦上，但結果欄位與判讀規則明顯擴張 | 後續獨立解讀系統 |
| 龜卜 | 龜甲灼裂的兆紋與相應占辭 | 古代「卜」；不是以六個爻值形成《周易》卦 | 不共用易卦引擎；需另立影像／兆紋規則與史料來源 |
| 鳥卦 | 由鳥選取籤牌、籤條或其他既定項目 | 臺灣民俗占法，結果通常不是本卦／之卦 | 不共用易卦引擎；需明確流派、牌組與授權語料 |
| 抽籤擲筊 | 籤號、籤詩及筊杯確認結果 | 可受易學影響，但不是六爻演算 | 不共用易卦引擎；需廟宇／籤系與授權語料 |
| 六壬神課 | 天地盤、四課三傳等課式 | 獨立術數，不是《周易》六十四卦起卦方式 | 若納入，視為獨立產品模組與 corpus |

歷史分類依據：傳統文獻有「龜為卜，策為筮」之分；龜卜觀察灼裂兆紋，易筮則以蓍策得數。《周易》產品不得因為現代口語都稱「卜卦」，便假設所有方法都輸出六十四卦。

### 3.1 MVP 的結果取得方式

以下是同一套《周易》六爻結果的輸入方式，不另稱為傳統卜法：

| 取得方式 | 原始輸入 | 每爻輸出 | MVP |
|---|---|---|---|
| 實體三錢手動輸入 | 每次三枚實體銅錢的二元面值 | 三個 2／3 相加為 6／7／8／9 | 是 |
| 六鍵時間取數 | 倒數後六個固定爻位按鈕的點擊經過時間 | elapsed milliseconds `% 8` 對應 6／7／8／9 | 是，明示為產品互動取數方式 |
| 三次二元操作小遊戲 | 每爻三次使用者操作 | 三個 2／3 相加為 6／7／8／9 | 否，未來候選 |

無論來源為何，之後都以同一個 6／7／8／9 爻值模型計算本卦、動爻與之卦；結果中仍須顯示取得方式及原始輸入紀錄。

## 4. 卜問結構候選

### 4.1 一卦問事

- 步驟：`當次問題`。
- 起卦次數：一次。
- 每步結果：一個完整《周易》結果。
- 定位：MVP 預設。

### 4.2 三卦推演

- 步驟一：`背景與根因`。
- 步驟二：`目前關鍵`。
- 步驟三：`可能趨勢`。
- 起卦次數：三次，各自完整起六爻。
- 定位：後續候選；明示為本站設計的卜問結構，不宣稱是固定古法。

### 4.3 五卦分析

- 步驟一：`內在狀態`。
- 步驟二：`外在條件`。
- 步驟三：`彼此互動`。
- 步驟四：`可能發展`。
- 步驟五：`可行行動方向`。
- 起卦次數：五次，各自完整起六爻。
- 不使用「最佳解決方案」，避免假設存在唯一解或保證結果。

## 5. 組合規則

- 每個 `ConsultationStep` 都有自己的子問題、次序與 `DivinationResult`。
- 《周易》步驟的結果是完整本卦／動爻／之卦，不把三者硬套成過去／現在／未來。
- 第一版同一個 Session 只使用一種卜法；跨方法佐證不列入 MVP。
- 同一結果可切換多個已核准的解讀資料集，但切換不得改變原始結果。
- 未完成目前步驟前不能顯示下一步結果。
- 多步驟結果必須逐步解讀，最後的總結只能引用各步已出現的內容。
- 外部 AI Context 需保留步驟邊界，不得把多個獨立卦合成一個卦。

## 6. 研究與內容 Gate

任何新卜法進入產品前，必須先確認：

1. 流派或規則版本。
2. 原始輸入與可重現演算。
3. 結果資料結構。
4. 解讀文本底本、授權與審校責任。
5. 是否涉及宗教儀式、實體動物或不可誤導的文化語境。
6. 能否和其他方法清楚分開，不偽稱為同一套《周易》規則。

## 7. 語料、分類與執行期組合

解讀規模採分層管理，避免為每種卦變 × 問題分類人工撰寫一篇完整解釋：

1. **基礎語料層**：固定經文與傳文、六爻及用九／用六；另以本卦／之卦配對保存焦氏易林林辭。完整易林目標為 4096 條，每筆各有來源、版本、修改聲明及審校狀態。
2. **卦級分類層**：按經確認的分類（例如事業、感情、財務、健康）建立每卦中性重點摘要，不為 4096 種易林配對各寫一份分類文。每條列經文依據、編者、版本與審校狀態；健康等敏感分類不得提供診斷或治療替代。
3. **規則層**：版本化保存朱熹考變占選文、卦形變化與其他具來源的演算規則。用神、六親等只由明確指定的流派引擎使用，不泛化到所有易卦占法。
4. **執行期組合層**：依問題分類、本卦、動爻、之卦與使用者選定的閱讀方式，挑出經文、易林及已審校分類摘要，保留各段來源 ID。第一版把整理後上下文提供複製到外部 AI；站內 LLM 是後續另行決策，不回寫為固定古籍／分類資料。

使用者提出的 `64 卦 × 分類` 是控制人工工作量的方向草案；分類名稱、是否每一分類都涵蓋 64 卦，仍需在後續內容規格確定。不得以「資料夠用」為由，把模型生成摘要冒充已審校分類層。
