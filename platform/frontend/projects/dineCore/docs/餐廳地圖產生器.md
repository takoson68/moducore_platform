# 餐廳地圖產生器

## 文件定位
本文件整理 DineCore 餐廳地圖產生器第一版（MVP）的功能範圍與操作流程。

目標是先建立一套可建立、編輯、儲存與重新載入的地圖編輯系統，作為後續桌位管理、櫃台營運與場域視覺化的基礎。

補充原則：

- 第一版先完成餐廳地圖產生。
- 下一階段桌位編輯仍放在同一個產生器內，不另開獨立頁面。
- 同一個產生器內分為兩個工作模式：
  - `Map Edit Mode`
  - `Table Edit Mode`

## 1. 地圖基本資料
每張地圖至少需要以下基本屬性：

- 地圖名稱 `name`
- 畫布寬度 `width`
- 畫布高度 `height`

規則如下：

- 以上屬性應可隨時修改。
- 畫布尺寸需與設定值即時綁定。
- 第一版不處理底圖匯入。
- 場域結構直接由編輯器內的繪圖工具建立。

## 2. 建立地圖流程
建立新地圖時，使用者流程如下：

1. 輸入地圖名稱。
2. 設定畫布尺寸。
3. 建立地圖。
4. 系統自動進入編輯模式 `Edit Mode`。

建立完成後，使用者即可直接開始繪製地圖內容。

## 3. 編輯介面結構
第一版編輯介面分為兩個主要區塊：

- 左側：
  - 網站導覽列
  - 負責系統頁面切換。
- 右側：
  - 工作區域 `Workspace`
  - `Workspace` 包含：
    - 編輯工具列 `Toolbar`
    - 地圖畫布 `Canvas`

介面原則如下：

- 工具列位於畫布上方。
- 畫布是主要操作區域。
- 所有地圖物件都繪製於畫布中。

## 4. 工具列設計
第一版工具列提供以下工具：

- `Polyline`
- `Rectangle`
- `Circle`
- `Text`

使用規則：

- 同一時間只允許一種工具處於啟用狀態。
- 工具僅用於新增地圖元素。
- 本系統不提供 `Select` 工具。
- 物件操作將透過單物件編輯模式 `Object Edit Mode` 完成。

補充規則：

- 在 `Edit Mode` 下，若某繪圖工具已啟用，點擊空白畫布代表開始建立該工具的新物件。
- 在 `Edit Mode` 下，若目前沒有任何繪圖工具啟用，點擊空白畫布不產生新物件。
- 第一版工具列僅服務 `Map Edit Mode`。
- 後續若切換到 `Table Edit Mode`，工具列將改為桌位相關工具，不與地圖繪圖工具混用。

## 5. 物件編輯模式（Object Edit Mode）
當使用者在 Edit Mode 中點擊畫布內的某個物件時，系統會進入該物件的編輯模式。

進入編輯模式後：

- 該物件顯示編輯控制，例如節點。
- 其他所有物件半透明顯示。
- 其他物件不可操作。
- 畫布只允許編輯當前物件。

此模式可避免同時誤操作多個物件，並保持操作焦點。

補充規則：

- `Edit Mode` 為地圖層級編輯模式。
- `Object Edit Mode` 為 `Edit Mode` 內的單物件聚焦編輯狀態。
- `Object Edit Mode` 不是獨立主模式。
- `Object Edit Mode` 是 `Map Edit Mode` 或 `Table Edit Mode` 底下的單物件聚焦編輯狀態。
- 在 `View Mode` 下，點擊物件只作為查看，不進入物件編輯模式。
- 進入 `Object Edit Mode` 後，工具列暫時鎖定。
- 在 `Object Edit Mode` 下，不允許切換其他繪圖工具。
- 上述限制會持續到退出該物件編輯模式為止。
- 在 `Object Edit Mode` 下，點擊空白畫布不會退出編輯模式。
- 退出 `Object Edit Mode` 僅能透過 `Esc` 或「完成編輯」按鈕。
- 進入 `Map Edit Mode` 或 `Table Edit Mode` 後，`Object Edit Mode` 才可能被啟動。

## 6. 折線工具 `Polyline`
折線工具是地圖繪製的核心功能，主要用於畫出：

- 餐廳外牆
- 隔間
- 區域邊界
- 動線邊界

### 6.1 操作流程
1. 點擊畫布新增第一個節點。
2. 持續點擊新增後續節點。
3. 系統依節點順序自動生成線段。
4. 使用雙擊或 `Enter` 結束繪製。

### 6.2 編輯折線
當使用者點擊折線物件時：

- 系統進入折線編輯模式。
- 顯示所有節點。
- 可拖曳節點調整形狀。
- 可刪除節點。
- 可新增節點。

同時：

- 其他物件半透明。
- 其他物件不可操作。

補充規則：

- 新增節點方式為點擊既有線段插入節點。
- 第一版不支援拖曳尾端延伸線段。
- 第一版不支援拆分 `polyline`。
- 正在繪製 `Polyline` 時，點擊既有物件不進入物件編輯模式。
- 正在繪製 `Polyline` 時，`Esc` 應優先作為取消當前繪製行為。
- 正在繪製 `Polyline` 且尚未完成時，不允許切換其他工具。

### 6.3 退出編輯模式
可透過以下方式退出：

- 點擊「完成編輯」按鈕。
- 按 `Esc`。

退出後：

- 所有物件恢復正常顯示。
- 系統回到一般操作狀態。

### 6.4 設計原則
第一版折線工具維持輕量化，不提供過度複雜的路徑能力。

第一版只處理：

- 節點新增
- 節點拖曳
- 節點刪除
- 水平吸附
- 垂直吸附

第一版不處理：

- 貝茲曲線
- 複雜路徑布林運算
- 進階向量編修功能

補充規則：

- 第一版只有 `polyline` 支援節點編輯。

## 7. 磁點吸附功能
為了更容易畫出直角場域結構，折線工具需提供磁點吸附功能。

### 7.1 前一節點吸附
新增節點時，系統以前一個節點作為基準：

- 若滑鼠水平偏差較小，吸附為水平線。
- 若滑鼠垂直偏差較小，吸附為垂直線。

此機制可快速畫出：

- 直角牆面
- 走道邊界
- 矩形區域輪廓

### 7.2 起點吸附
在繪製最後一段線時，系統除參考前一節點外，也會參考起始節點位置。

若滑鼠接近起點的 `x` 或 `y` 軸位置，系統自動吸附，使最後一段線更容易與起點對齊。

此機制有助於：

- 收尾形成整齊外框
- 建立更準確的矩形或封閉區域
- 降低手動對齊成本

## 8. 矩形與圓形工具
矩形與圓形工具用於繪製簡單區域，例如：

- 包廂區
- 吧台
- 廚房
- 區域框

### 8.1 操作方式
1. 點擊並拖曳畫布。
2. 生成圖形。
3. 放開滑鼠完成。

### 8.2 編輯圖形
當使用者點擊圖形時：

- 系統進入該圖形的物件編輯模式。
- 可操作：
  - 移動
  - 調整大小
  - 刪除

同時：

- 其他物件半透明。
- 其他物件不可操作。

補充規則：

- `rect`、`circle` 僅支援移動、調整大小、刪除。
- `rect`、`circle` 不支援節點級編輯。

## 9. 文字工具
文字工具用於標示區域名稱，例如：

- 內用區
- 戶外區
- 包廂
- 吧台

第一版需支援：

- 新增文字
- 編輯文字內容
- 拖曳文字位置

文字被點擊時也會進入物件編輯模式。

補充規則：

- `text` 僅支援移動、調整大小、刪除。
- `text` 不支援節點級編輯。
- 第一版 `text` 的調整大小以文字框範圍為主，不延伸為完整排版系統。

## 10. 地圖儲存與重新編輯
完成繪製後，系統需能儲存完整地圖資料，包括：

- 地圖基本資料
- 所有繪圖物件
- 各物件幾何資料、節點與座標

系統需支援以下能力：

- 重新載入地圖
- 再次進入編輯模式
- 在既有地圖上持續修改

### 10.1 模式區分
系統需區分兩種模式：

- `View Mode`
  - 用於：
    - 櫃台桌況顯示
    - 場域可視化
  - 不允許編輯。
- `Edit Mode`
  - 用於：
    - 地圖繪製
    - 地圖修改
    - 物件編輯
  - 內部再細分為：
    - `Map Edit Mode`：負責場域圖形與文字編輯
    - `Table Edit Mode`：負責桌位新增、移動、編輯與刪除

補充規則：

- 地圖載入後預設為 `View Mode`。
- 只有當使用者主動進入 `Edit Mode`，才允許修改地圖。
- 使用者由 `Edit Mode` 進入實際工作時，需明確選擇 `Map Edit Mode` 或 `Table Edit Mode`。
- `Map Edit Mode` 與 `Table Edit Mode` 之間的切換，必須先退出當前的 `Object Edit Mode`。
- 若目前存在尚未完成的繪製行為，應先完成或取消後，才允許切換工作模式。

## 11. MVP 功能範圍
第一版地圖產生器收斂為以下能力：

- 建立地圖
- 修改地圖名稱與尺寸
- 折線繪製
- 折線節點編輯
- 水平與垂直吸附
- 矩形繪製
- 圓形繪製
- 文字標示
- 單物件編輯模式
- 儲存地圖
- 重新載入地圖

## 12. 下一階段銜接
完成以上 MVP 後，再進入下一階段：

- 在地圖上加入桌位模型
- 桌位與營運資料串接
- 接入櫃台營運系統
- 實現桌況視覺化管理

補充規則：

- 桌位編輯不是獨立產生器，而是同一個餐廳地圖產生器中的第二工作階段。
- 畫面層先維持同一個 `Workspace`。
- 邏輯與資料結構上需與地圖物件分流。

## 12.1 Table Edit Mode 最低互動規則

為了讓桌位編輯可直接進入實作，第一版需定義最小互動流程。

### 1. 新增桌位

- 工具列提供 `Table` 工具。
- 啟用後，點擊畫布即建立一個桌位物件。
- 桌位使用預設尺寸，例如 `80 x 80`。
- 建立位置以滑鼠點擊的世界座標為準。

補充規則：

- 新建立桌位後，不自動進入 `Object Edit Mode`。
- 桌位加入 `tables` 集合，而非 `objects`。

### 2. 選取桌位

- 在 `Table Edit Mode` 下點擊桌位，進入該桌位的 `Object Edit Mode`。
- 同一時間只允許一個桌位進入編輯。

補充規則：

- 點擊地圖圖形 `polyline`、`rect`、`circle` 不應有反應。
- 命中判定只針對 `tables`。

### 3. 桌位編輯（Object Edit Mode）

進入桌位編輯後，至少支援：

- 拖曳位置 `move`
- 調整大小 `resize`
- 刪除桌位 `delete`

補充規則：

- 顯示 `bounding box` 控制點。
- 第一版不支援旋轉。

### 4. 刪除桌位

可透過以下方式刪除：

- `Delete` 鍵
- UI 按鈕「刪除」

刪除後：

- 自動退出 `Object Edit Mode`。

### 5. 點擊空白畫布

- 若有啟用 `Table` 工具，建立新桌位。
- 若沒有啟用工具，不做任何事。
- 不會退出 `Object Edit Mode`。

### 6. 模式限制

- 在 `Table Edit Mode` 下，不允許建立地圖圖形。
- 在 `Table Edit Mode` 下，不允許編輯 `objects`。
- 在桌位的 `Object Edit Mode` 下，工具列鎖定。
- 在桌位的 `Object Edit Mode` 下，不允許切換工具。

### 7. 資料結構（Table）

桌位需獨立於地圖物件：

```json
{
  "id": "table_01",
  "x": 300,
  "y": 200,
  "width": 80,
  "height": 80,
  "label": "A1"
}
```

補充規則：

- 使用 world 座標。
- `render order` 可依陣列順序或 `z-index` 控制。
- `Table Edit Mode` 仍沿用同一個畫布與同一個 `Workspace`。
- 進入 `Table Edit Mode` 後，使用者只操作桌位相關物件，不直接編輯地圖圖形。
- 桌位物件也可進入 `Object Edit Mode`，但其編輯內容僅限桌位自身。
- 桌位與地圖物件若同時存在於視圖中，命中與操作優先序仍需遵守模式邊界。

## 13. 地圖資料結構
為了支援地圖儲存、重新載入與後續桌位擴充，系統需採用清晰且可擴展的資料結構。

第一版資料結構分為三個層級：`Map`、`Object`、`Node`。

### 13.1 Map（地圖）
`Map` 代表一張餐廳地圖。

每張地圖包含基本屬性與所有繪圖物件。

必要欄位：

- `id`
- `name`
- `width`
- `height`
- `objects`

範例：

```json
{
  "id": 1,
  "name": "一樓內用區",
  "width": 1200,
  "height": 800,
  "objects": []
}
```

補充規則：

- `objects` 陣列順序即為 `render order`。
- 陣列後方物件顯示在上層。
- 新建立物件預設加入陣列尾端。
- 物件重疊時，命中判定優先以較上層物件為準。
- 第一版 `Map` 使用 `objects` 儲存地圖物件。
- 下一階段桌位資料建議獨立為 `tables` 集合，不直接混入 `objects`。
- 原因是桌位屬於營運物件，不等同一般場域圖形。

### 13.2 Object（地圖物件）
`Object` 代表畫布上的一個元素，例如：

- 折線
- 矩形
- 圓形
- 文字

必要欄位：

- `id`
- `type`
- `data`

範例：

```json
{
  "id": "obj_01",
  "type": "polyline",
  "data": {}
}
```

`type` 可能包含：

- `polyline`
- `rect`
- `circle`
- `text`

### 13.3 Node（節點）
`Node` 主要用於折線物件，代表一個節點座標。

節點結構：

- `x`
- `y`

範例：

```json
{
  "type": "polyline",
  "data": {
    "points": [
      { "x": 100, "y": 100 },
      { "x": 400, "y": 100 },
      { "x": 400, "y": 300 }
    ]
  }
}
```

### 13.4 其他物件資料
矩形：

```json
{
  "type": "rect",
  "data": {
    "x": 200,
    "y": 200,
    "width": 300,
    "height": 150
  }
}
```

圓形：

```json
{
  "type": "circle",
  "data": {
    "x": 220,
    "y": 120,
    "width": 160,
    "height": 160
  }
}
```

文字：

```json
{
  "type": "text",
  "data": {
    "x": 150,
    "y": 120,
    "width": 120,
    "height": 40,
    "content": "內用區"
  }
}
```

### 13.5 設計原則
第一版資料結構需遵循以下原則：

- `Map` 僅負責管理地圖尺寸與物件集合。
- `Object` 負責描述畫布元素。
- `Node` 僅處理座標資料。
- 所有圖形皆可透過 `type + data` 擴展。
- 第一版圖形資料盡量統一使用矩形 `bounding box`。
- 上述作法可簡化拖曳、縮放與命中判定。
- `circle` 以外接矩形作為第一版幾何描述基礎。
- 第一版 `circle` 應維持 `width = height`，避免在資料層直接退化為橢圓。

此結構可在未來直接擴充：

- 桌位物件 `table`
- 區域物件 `zone`
- 圖層 `layer`
- 群組 `group`

而不需要重構整個資料模型。

## 14. 座標系統與縮放規則
為了支援穩定的地圖編輯、縮放顯示與後續拖動畫布能力，地圖系統必須明確區分「世界座標」與「畫面座標」。

### 14.1 地圖使用世界座標
地圖必須有一套固定的內部座標系統，不可直接以目前畫面顯示大小作為真實資料。

例如一張地圖可定義為：

- 地圖寬度：`1200`
- 地圖高度：`800`

所有物件都應以這組地圖原始座標儲存，例如：

- `x`
- `y`
- `width`
- `height`

設計規則如下：

- 資料永遠儲存地圖原始座標。
- 不儲存畫面縮放後的座標。
- 同一份資料在不同縮放倍率下必須保持一致。

### 14.2 縮放只影響顯示，不改變資料
當畫布縮放時，改變的是畫面呈現大小，不是地圖資料本身。

例如畫布放大 `150%`：

- 畫面看起來變大。
- 但資料仍維持在原本 `1200 x 800` 的世界座標系統中。

轉換公式如下：

```text
screenX = worldX * scale
screenY = worldY * scale
```

反向換算時：

```text
worldX = screenX / scale
worldY = screenY / scale
```

### 14.3 平移與縮放需分開處理
若未來要支援拖動畫布，座標轉換需再加入平移量。

完整公式如下：

```text
screenX = worldX * scale + offsetX
screenY = worldY * scale + offsetY
```

第一版建議如下：

- 先支援 `scale`
- 暫不支援 `offsetX / offsetY`
- 平移能力留待下一階段實作

這樣可先把資料模型與互動模型穩定下來，再擴充畫布視角移動能力。

### 14.4 事件座標需先轉回世界座標
當滑鼠點擊或拖曳畫布時，不應直接使用 `clientX / clientY` 作為地圖資料座標。

正確流程應為：

1. 先取得滑鼠相對於畫布的座標。
2. 扣掉畫布在畫面上的位置。
3. 再除以目前縮放比例。
4. 轉換為世界座標後，再寫入地圖資料。

這樣可確保：

- 不同縮放倍率下新增節點位置仍然正確。
- 拖曳物件時不會因畫面縮放而產生偏移。
- 未來加入平移後，仍可沿用同一套座標轉換邏輯。

### 14.5 第一版實作原則
第一版地圖編輯器在座標系統上應遵守以下原則：

- 地圖資料一律使用世界座標。
- 畫面縮放僅影響顯示層。
- 互動事件必須先轉回世界座標再處理。
- `scale` 與未來的 `offset` 必須在設計上保留分層。
- 不可將畫面顯示座標直接寫回資料模型。
