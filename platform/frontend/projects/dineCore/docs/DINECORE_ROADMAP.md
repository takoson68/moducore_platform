# DineCore 開發順序與里程碑

## 0. 文件用途
本文件定義 DineCore 目前採用的實際開發節奏。

本文件用途為：
- 反映目前已完成的架構工作
- 避免文件里程碑與實際開發脫節
- 讓後續工作能以「先成形、再打通、再營運」的順序推進

---

## 1. 當前開發策略
- 先把顧客端、商家端、資料模型、API 契約與 mock 流一起立起來
- 再逐步把顧客端主流程從可展示提升到可驗收
- 再補商家端營運閉環與角色控制
- 最後才進入正式營運能力，例如報表、關帳與稽核

這代表 DineCore 目前不是嚴格線性 milestone 開發，而是：

1. 先完成整體骨架
2. 再打通重點流程
3. 再補深度功能

---

## 2. Phase A：整體架構成形
目標：
- 先把系統的大架構、頁面地圖、資料模型、API 契約與前端模組骨架立起來

目前狀態：
- 已完成

已完成內容：
- `dineCore系統規格書.md`
- `DINECORE_USER_STORIES.md`
- `DINECORE_MODULE_MAP.md`
- `DINECORE_M1_DATA_MODEL.md`
- `DINECORE_M1_API_CONTRACT.md`
- `entry / menu / cart / checkout / order-tracker`
- `counter / kitchen / dashboard`
- 顧客端 web 內容版骨架
- 顧客端 mock service 流程

完成條件：
- 核心模組皆已有合法入口與頁面骨架
- 顧客端與商家端頁面流可被展示
- 資料模型與 API 契約已收斂到可開發程度

---

## 3. Phase B：顧客端主流程打通
目標：
- 把顧客端從「可展示」提升為「可驗收的完整操作流程」

目前狀態：
- 進行中

範圍：
- `entry`
- `menu`
- `cart`
- `checkout`
- `order-tracker`

重點工作：
- 完整的桌號入口判斷與例外處理
- 菜單與品項客製互動
- 子購物車新增、切換、編輯與合單
- 防重複送單
- 成功頁與追單頁真實連動

目前已完成：
- 入口載入桌號 mock context
- 菜單載入與分類切換
- 可加入購物車
- 可切換子購物車
- 可在購物車增減數量
- 可送出 mock 訂單
- 成功頁與追單頁可讀取 mock 訂單

尚未完成：
- 客製選項互動式編輯
- 備註編輯
- 錯誤提示與 loading 狀態整理
- 狀態頁與桌號不可用分支

驗收條件：
- 單桌多人點餐流程可完整跑通
- 合單後仍保留按人分帳資訊
- 顧客可從掃碼走到追單，不需手動修資料

---

## 4. Phase C：商家端營運閉環
目標：
- 讓商家端能接住顧客端送出的資料，形成營運閉環

目前狀態：
- 骨架完成，資料流未完成

範圍：
- `counter`
- `kitchen`
- `dashboard`

重點工作：
- 櫃台訂單列表接上同一套 mock / 後續真實資料流
- 廚房看板讀取未完成訂單
- 櫃台付款確認與狀態更新
- 店長總覽摘要資料

目前已完成：
- 商家端模組骨架
- 路由與 store 骨架
- 工作台式版面容器

尚未完成：
- 商家端 mock service 串接
- 顧客端與櫃台／廚房狀態聯動
- dashboard 真實摘要來源

驗收條件：
- 顧客送出的訂單可被櫃台與廚房看到
- 櫃台與廚房的狀態更新會反映回顧客端

---

---

## 6. Phase E：報表、稽核與關帳
目標：
- 補齊正式營運所需的報表、操作留痕與帳務控制

目前狀態：
- 未開始

規劃模組：
- `reports`
- `audit-close`

主要內容：
- 日報表與匯出
- 操作紀錄
- 每日關帳
- 店長解鎖

---

## 7. 實際優先順序
1. 先完成 Phase B，把顧客端主流程打通
2. 再完成 Phase C，把商家端接上同一套資料流
3. 接著才做 Phase D 的管理後台
4. 最後做 Phase E 的正式營運能力

---

## 8. 目前風險
1. 文件已定義的 stories 是正確的，但原本 milestone 節奏已不再適用舊版本描述
2. 顧客端目前已有 mock 互動，但商家端還沒接上同一套資料流，容易產生假整合
3. 若過早往下做報表與關帳，會把尚未穩定的訂單模型提前鎖死

---

## 9. 目前建議的下一步
1. 先把商家端 `counter / kitchen / dashboard` 接到現有 mock service
2. 再補顧客端剩餘互動，例如客製選項、備註與狀態頁
3. 等 Phase B 與 Phase C 穩定後，再開 Phase D
