# 購物車取消併單，並且一人一單執行書

## 0. 可行性驗證結論
- 結論：可行，但需分兩階段執行。
- 目前系統現況：
  - `DineCoreGuestApiController::resolveActiveOrderForTable()` 會讓同桌共用同一張未結帳訂單。
  - `DineCoreGuestApiController::shouldExposeSessionInCartPayload()` 目前固定 `return true`，因此購物車會顯示多人。
  - `dinecore_table_sessions` 目前設計偏向「每桌單一 active session + 單一 order_id」。
- 代表意義：
  - 第一階段可先做到「畫面與 API 僅顯示本人」，不動資料表。
  - 第二階段再做到「真正一人一單（同桌多張 order）」，需改後端 session/order 綁定邏輯。

## 1. 目標
- 第一階段（本次）：取消併單體驗，顧客端只看自己的購物車與自己的訂單資料。
- 第二階段：改為真正一人一單（同桌不同顧客建立不同 order）。

## 2. 執行步驟（第一階段，低風險）

### 步驟 1：後端只回傳本人 cart
- 檔案：`platform/backend/src/Controllers/DineCoreGuestApiController.php`
- 修改：
  1. `shouldExposeSessionInCartPayload(array $session, array $items, string $currentCartId)`
  2. 改為僅在 `session['cart_id'] === $currentCartId` 時回傳 `true`
- 目的：購物車 API 不再回傳其他人 cart。

### 步驟 2：checkout summary 只顯示本人
- 檔案：`platform/backend/src/Controllers/DineCoreGuestApiController.php`
- 修改：
  1. `buildCheckoutSummaryForBatch()` 目前會組 `persons` 陣列
  2. 改為僅保留 `orderingSession` 對應的 cart/person
- 目的：結帳頁不顯示同桌其他人的品項與金額。

### 步驟 3：前端移除多人 cart 切換 UI
- 檔案：`platform/frontend/projects/dineCore/modules/cart/pages/CartPage.vue`
- 修改：
  1. 移除 `section.cart-switcher`
  2. `viewingCart` 固定使用 `orderingCart`
  3. `participantCount` 文案改成「僅顯示本人」
- 目的：視覺與交互完全取消多人切換。

### 步驟 4：store 固定 viewingCart = orderingCart
- 檔案：`platform/frontend/projects/dineCore/modules/cart/store.js`
- 修改：
  1. `load()` 成功後強制 `viewingCartId = orderingCartId`
  2. `setViewingCart()` 保留但不在 UI 暴露
- 目的：避免殘留狀態切到他人 cart。

### 步驟 5：驗證與建置
- 指令：
  1. `php -l platform/backend/src/Controllers/DineCoreGuestApiController.php`
  2. `cd platform/frontend`
  3. `set VITE_PROJECT=dineCore`（Windows）
  4. `npm run build`
- 驗收：
  1. 同桌兩人同時在線，彼此看不到對方品項
  2. 兩人各自可正常加減品項與送單
  3. 既有櫃台/廚房流程不壞

## 3. 執行步驟（第二階段，真正一人一單）

### 步驟 1：重構同桌訂單綁定策略
- 檔案：`platform/backend/src/Controllers/DineCoreGuestApiController.php`
- 修改重點：
  1. `resolveActiveOrderForTable()` 不再以桌號復用同一 open order
  2. 改為「每個 ordering session 若無 open order 就建立新 order」

### 步驟 2：調整 table session 結構使用方式
- 現況限制：`findTableSessionForUpdate()` 會刪除同桌重複 row，且 row 內只有單一 `order_id`。
- 建議做法（二選一）：
  1. 保留單 row，但 `guest_state_json` 內每人持有獨立 `order_id`（推薦）
  2. 改成同桌可多 row，停止刪除 duplicate row

### 步驟 3：提交購物車改寫為 session 對應 order
- 函式影響：
  1. `addItem()` / `changeItemQuantity()` / `updateItem()`
  2. `checkoutSubmit()`
- 原則：所有 cart item 寫入該 session 的 `order_id`，不共享他人 order。

### 步驟 4：員工端同桌多單顯示
- 檔案：
  1. `platform/backend/src/Controllers/DineCoreStaffApiController.php`
  2. `platform/frontend/projects/dineCore/modules/counter/pages/CounterOrdersPage.vue`
- 目標：A01 可同時顯示多筆 `order_no`，每筆獨立付款狀態。

### 步驟 5：資料庫索引與保護
- 建議新增索引：
  1. `dinecore_orders(table_code, payment_status, created_at)`
  2. `dinecore_cart_items(order_id, cart_id, batch_id)`
- 目標：避免 session 併發寫入造成重複或查詢過慢。

## 4. 風險與回滾
- 風險：第二階段涉及核心建單流程，需先在 staging 壓測。
- 回滾策略：
  1. 保留第一階段版本 tag
  2. 以 feature flag 控制「單桌共單 / 一人一單」
  3. 發生異常可立即切回「單桌共單 + 本人視角」

## 5. 完成定義（DoD）
- 第一階段完成：
  1. 顧客端看不到他人 cart / summary
  2. UI 無併單與多人切換入口
- 第二階段完成：
  1. 同桌不同顧客建立不同 order_no
  2. 各自付款互不影響
  3. 櫃台可查看同桌多單
