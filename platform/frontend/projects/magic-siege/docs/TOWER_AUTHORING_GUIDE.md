# 塔型新增與驗收指南

本文件是「攻破魔法城」新增塔型的固定流程。新增塔型必須同時完成規則、資料、畫面、互動與測試，不接受只增加一個外觀或名稱。

## 目前塔型

| ID | 名稱 | 外觀 | 攻擊規則 |
|---|---|---|---|
| `single` | 單體塔 | 藍色三角形 | 對單一目標造成完整傷害 |
| `aoe` | 群攻塔 | 紫色方形 | 命中目標，並對 72px 內其他敵人造成 55% 傷害 |
| `beam` | 魔法射線塔 | 粉色五角形 | 鎖定最先進入射程的敵人並持續扣血，直到死亡或離開射程 |

## 新增流程

### 1. 先定義玩法

新增前先寫清楚：

- 塔型 ID、顯示名稱與定位。
- 建造成本、升級成本、射程、傷害、冷卻。
- 目標選擇規則與是否有範圍傷害。
- 是否對 Boss 有額外規則。
- 是否有範圍、穿透、減速、護盾、暴擊或其他特殊功能。
- 與現有單體塔、群攻塔的差異，以及預期使用時機。

### 2. 更新模擬器資料

在 `modules/battlefield/simulation.js`：

- 將塔型加入 `towerTypes`。
- 建塔時把 `type` 寫入塔實例。
- 若有特殊攻擊，更新子彈、命中與傷害計算。
- 不要用畫面顏色或文字推斷玩法規則。
- 特殊功能要有可測試的資料欄位或獨立規則函式。

### 3. 更新右側塔型選擇器

在 `modules/battlefield/sketch.js`：

- 為每個塔型增加一個可點擊的圖形卡片。
- 選中塔型必須有清楚焦點框或底色。
- 建造按鈕必須建立目前焦點塔型。
- 塔放置到地圖後，外觀必須能和其他塔型區分。
- 手機尺寸下，選擇卡與建造按鈕不可互相覆蓋。

### 4. 補測試

至少新增以下測試：

- 可明確指定新塔型。
- 建造後塔實例保留正確 `type`。
- 新塔型的傷害／範圍規則有效。
- 單體塔既有行為不被改變。
- 第 10 波 Boss 與新塔型互動符合設計。

### 5. 驗收與部署

```bash
node --test platform/frontend/projects/magic-siege/modules/battlefield/simulation.test.mjs
npm run build -- --mode staging
```

本機確認順序：

1. 先在正確的 `magic-siege` 本機 Project 啟動頁面。
2. 點選新塔型圖卡，確認焦點狀態。
3. 點建造，確認地圖外觀與塔型一致。
4. 開始一波，確認攻擊規則與傷害結果。
5. 再建立單體塔，確認原本塔型仍正常。
6. 通過手機尺寸與觸控點擊檢查後，才建立部署 Tag。

## 文件同步規則

若新增塔型改變成本、關卡平衡、Boss 規則或五關教學節奏，必須同步更新：

- `LEVEL_DIFFICULTY_MATRIX.md`
- `LEVEL_AUTHORING_GUIDE.md`
- `MILESTONE_PLAN.md` 或相關企劃決策文件
