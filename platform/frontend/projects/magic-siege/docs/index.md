# 攻破魔法城專案文件導讀

## 範圍

本目錄只保存 `magic-siege` 的玩法企劃、MVP 規格與專案內補充資料。平台 Game Runtime 契約仍以 `platform/frontend/src/app/game/index.md` 與原始碼為現況依據。

## 閱讀順序

1. `塔防遊戲 MVP 企劃書_v1.0.md`：「攻破魔法城」玩法、幾何原型範圍、數值起點與驗收條件。
2. `MILESTONE_PLAN.md`：實作階段、每階段產出與完成 Gate。
3. `PROGRESS.md`：最新停止點、驗證、風險與唯一下一步。
4. `ModuCore × 塔防遊戲：容器使用策略 v1.0.md`：專案如何使用現有 Game Runtime；實際架構決策另見 `../decisions/`。
5. `assets/geometry-prototype-screen-v1.png`：第一版幾何原型完整畫面稿，作為地圖、HUD、建造面板與操作層級的實作參考。
6. `LEVEL_2_MAP_DESIGN.md`：第二關地圖路線、障礙與關卡切換規格。

## 畫面稿狀態

- `geometry-prototype-screen-v1.png` 是討論用原型，不是正式美術或需要逐像素還原的最終畫面。
- 實作應保留其資訊層級與互動區塊，但必須回到企劃書的 12 × 9 地圖、道路座標、數值與幺何原型邊界進行實作。
- 畫面稿中的文字、圖示、色彩、間距與城堡造型都可在實作或試玩時調整。

## Infinitode 2 復刻學習定位

- 本專案的第一階段，有意識地以 `Infinitode 2` 為主要參考，復刻其核心操作節奏與資訊表現邏輯，作為第一款遊戲的學習路徑。
- 每次設計建造、選塔、升級、拆除、射程、波次與戰鬥資訊互動時，應先對照此學習目標，避免在尚未掌握核心循環前不斷改寫基礎交互。
- 復刻對象是玩法模式、互動節奏與資訊層級；不得複製其程式碼、美術、音效、文字、關卡資料或精確平衡數值。
- 有可玩樣本後，可依實際試玩發現調整或建立自己的特色；變更必須回寫企劃或決策文件。

## 文件邊界

- 企劃書是玩法預期與業務規則來源。
- 原始碼與測試是實作現況來源。
- 兩者不一致時，必須分別說明，不得默默覆蓋。
