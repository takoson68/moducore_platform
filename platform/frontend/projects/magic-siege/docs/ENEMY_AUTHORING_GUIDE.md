# 怪物新增與驗收指南

本文件是「攻破魔法城」新增怪物的固定流程。怪物不可只增加名稱與外觀；所有速度、血量、突破與特殊能力都必須先定義，再接入波次與測試。

## 目前怪物欄位

| 欄位 | 用途 |
|---|---|
| `id`／種類 | 程式識別與顯示分類，例如 `small`、`large`、`boss` |
| `hp` | 基礎生命值，會再乘上關卡難度倍率 |
| `speed` | 路徑移動速度 |
| `radius` | 碰撞、子彈命中與畫面尺寸基準 |
| `reward` | 被擊殺時取得的金幣 |
| `breachDamage` | 抵達城堡時扣除的生命 |
| 外觀 | 顏色、尺寸、血條與辨識圖形 |
| 特殊能力 | 例如護盾、分裂、加速、治療、隱形或抗範圍傷害 |

## 新增流程

### 1. 先寫怪物設計

新增前先確認：

- 它和小怪、大怪、Boss 的主要差異。
- 速度、血量、突破傷害、獎勵的預期範圍。
- 出現在哪些關卡與波次，是否只在第 10 波出現。
- 玩家應該用哪種塔型應對。
- 是否需要特殊提示、血條或 Boss 標記。

### 2. 更新怪物資料

在 `modules/battlefield/simulation.js`：

- 將種類加入 `enemyTypes`。
- 在 `waveConfig` 或波次產生規則中指定出現位置。
- 透過 `enemyStats` 套用關卡倍率，不要在單一波次硬編倍率。
- 特殊能力必須有獨立欄位或函式，不要把規則藏在畫面程式。

### 3. 更新戰鬥行為

依能力需要更新：

- 生成與移動。
- 子彈命中、範圍傷害與抗性。
- 突破城堡與生命扣除。
- 擊殺獎勵與波次結算。
- 暫停、加速、自動下一波時的行為一致性。

### 4. 更新畫面辨識

在 `modules/battlefield/sketch.js`：

- 不同種類必須能靠形狀、顏色或尺寸快速辨識。
- Boss 必須有明顯尺寸與血條差異。
- 特殊能力發動時要有可讀提示，不能只靠數值變化猜測。
- 手機畫面不可讓怪物血條或提示超出地圖區域。

### 5. 補測試

至少新增以下測試：

- 波次會產生正確種類與數量。
- 速度與路徑距離符合預期。
- 血量、突破傷害、獎勵正確套用。
- 新怪物不會破壞既有小怪、大怪與 Boss 行為。
- 新怪物和單體塔、群攻塔互動正確。
- 第 10 波勝利／失敗條件仍正確。

## 塔與怪物的共同規則

新增塔或怪物都必須同步完成：

1. 玩法定義。
2. 模擬器資料與行為。
3. 畫面辨識與 UI 選擇／提示。
4. 單元測試與完整波次測試。
5. 本機 Project 驗證。
6. 手機觸控驗證。
7. 文件與部署版本紀錄。

## 建議的新增順序

先增加一個有明確定位的怪物，再增加塔型來形成克制關係；不要同時新增大量種類，否則難以判斷是數值、操作還是規則造成問題。
