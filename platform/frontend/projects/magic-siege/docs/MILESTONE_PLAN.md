# 攻破魔法城｜MVP 里程碑計畫

> 狀態：active｜建立日期：2026-10-22｜目標：完成可從第 1 波玩到第 10 波的幾何塔防 MVP

## 0. 文件用途

本文件定義 `magic-siege` 的實作順序、每個里程碑的邊界、完成 Gate 與接續原則。

- 本文件管理「先做什麼、後做什麼」。
- `PROGRESS.md` 只記錄當前停止點、最新驗證與唯一下一步。
- 玩法與數值仍以 `塔防遊戲 MVP 企劃書_v1.0.md` 為準。
- 每個里程碑必須通過 Gate，才能進入下一階段。

## 1. 範圍原則

- 先完成幾何原型，不在 MVP 階段開始正式美術。
- 以 `Infinitode 2` 的核心操作體驗與資訊層級為學習參考，不複製受保護的表達或資產。
- 每個里程碑只引入完成當前 Gate 所需的最小能力。
- 試玩中發現的業務邏輯缺口，先回寫企劃或決策，再修改實作。

## 4. M1：靜態幾何畫面

### 目標

將 `docs/assets/geometry-prototype-screen-v1.png` 的資訊架構實作成真實 dev 畫面，但不實作戰鬥邏輯。

### 產出

- 12 × 9 格地圖、連續道路、障礙、起點與魔法城。
- 頂部 HUD：標題、波次、生命、金幣、暫停。
- 右側上下文面板：空格、砲塔與不可建造格的顯示狀態。
- 建造按鈕、開始下一波按鈕、格子選取、砲塔射程。
- 幾何化的靜態砲塔、敵人、子彈與城堡示意。

### 不包含

- 敵人移動、攻擊、傷害、經濟計算或波次生成。
- 正式美術、音效或特效。

### Gate

- [x] dev 畫面可在桌面瀏覽器完整顯示，不溢出主畫面。
- [x] 道路、可建造、障礙、已佔用與選取狀態可一眼辨識。
- [x] 點選格子會更新右側面板，不會同時觸發其他區域。
- [x] 畫面與第一版稿的資訊層級一致，不要求逐像素還原。
- [x] `magic-siege` 建置通過，且現有 `test:game` 不退化。

### 結果

- ✅ Gate 已全部通過，M1 確認完成（2026-10-22）。
- 人工畫面驗證：dev 頁完整顯示；點選既有魔法塔後，選取框、射程圈與右側資訊同步更新。
- 自動驗證：Production Build 通過；既有 `test:game` 8/8 通過。

## 5. M2：第一個可玩垂直切片

### 目標

在 M1 畫面上完成最小遊戲循環，讓玩家真正做出一次建造與防守決策。

### 產出

- 用 10 金幣在合法格建造一座 Lv.1 魔法塔。
- 手動開始第 1 波，依固定間隔生成小怪。
- 敵人沿固定路徑移動。
- 砲塔鎖定最近有效目標，發射可見追蹤子彈。
- 子彈命中才造成傷害；擊殺與突破分別更新金幣與基地生命。
- 暫停、恢復與重新開始。

### Gate

- [x] 第 1 波可完整進入、運行與結束。
- [x] 同一敵人只發放一次擊殺獲利，死亡與突破不同時發生。
- [x] 暫停期間不進行移動、冷卻、出怪、子彈或收入計時。
- [x] 重開後不殘留前一局的實例、事件或計時器。
- [x] 本階段新增的狀態與服務只存在遊戲私有 Container。

### 結果

- ✅ Gate 已全部通過，M2 確認完成（2026-10-22）。
- 人工實玩（當時建造費 50）：建塔後金幣 100→50；第 1 波結算為擊殺 3、突破 2、金幣 65、生命 18。建造費已於後續試玩決策改為 10。
- 暫停後畫面與所有遊戲時間停止；恢復後從原狀態繼續。
- 重開後回到生命 20、金幣 100、第 1 波準備階段，且塔、敵人、子彈與計時狀態皆清空。
- 自動驗證：M2 simulation 3/3、Production Build、既有 `test:game` 8/8 全數通過。

## 6. M3：完整砲塔與經濟操作

### 產出

- Lv.1 至 Lv.3 升級、攻擊數值、射程與冷卻。
- 拆除砲塔與累計投資 50% 無條件捨去退款。
- 出怪期間每秒被動收入與擊殺獲利。
- 戰鬥中可建造、升級與拆除。
- 升級、拆除、舊子彈與鎖定目標的邊界規則。

### Gate

- [x] 扣款、退款、被動收入與擊殺獲利均為整數且符合企劃。
- [x] 金幣不足與最高等級狀態不可執行對應操作。
- [x] 同一格無法重複建塔，拆除後立即恢復可建造。
- [x] 最後一隻敵人生成後停止被動收入，不可透過留怪無限獲利。

### 結果

- ✅ Gate 已全部通過，M3 確認完成（2026-10-22）。
- 人工操作：建造 100→90、Lv.2 升級 90→15、累計投資 85、拆除退款 42 後為 57；戰鬥中另格建塔成功。
- 舊子彈保留發射時傷害；升級影響後續子彈；拆塔不刪除已發射子彈。
- 自動驗證：M3 simulation 5/5、Production Build、既有 `test:game` 8/8 全數通過。

## 7. M4：雙敵人與十波流程

### 產出

- 小怪與大怪的獨立類型預設與實例狀態。
- 企劃書定義的 10 波數量與固定出怪順序。
- 準備／戰鬥階段切換、波次結束、第 10 波勝利與基地歸零失敗。
- 勝利／失敗畫面與完整重開。

### Gate

- [x] 10 波可由開始完整玩到勝利或失敗。
- [x] 本波敵人全部生成，且場上無存活敵人，才進入波次結束。
- [x] 基地歸零優先於第 10 波完成判定。
- [x] 每波敵人數量、類型與順序可重現。

### 結果

- ✅ Gate 已全部通過，M4 確認完成（2026-10-22）。
- 小怪與大怪具有獨立 HP、速度、半徑、獎勵與突破傷害；固定十波配置由純函式產生，可重現且第一隻固定為小怪。
- 第 10 波完成後顯示獨立的全畫面慶祝結尾與戰績，失敗亦有對應結局畫面；兩者皆可重新開始。
- 人工實玩：第 1 波結束後進入第 2 波準備，HUD、進度點與開始按鈕同步更新，生命及金幣延續，場上物件清空。
- 自動驗證：simulation 7/7 覆蓋十波配置、勝利、失敗優先與既有經濟規則；Production Build 與 `test:game` 8/8 通過。

## 9. M6：正式美術與個性化（延後）

只在 M5 通過後重新規劃。可能包含世界觀、角色、正式城堡與砲塔、動畫、音效、新塔種或專屬特色；目前不納入 MVP 估算與完成判定。

## 10. 進度接續規則

每次停止工作前，必須更新 `PROGRESS.md`：

1. 當前里程碑與階段狀態。
2. 本次完成的產出。
3. 已執行的測試、建置與人工驗證。
4. 已知問題與未驗證風險。
5. 唯一下一步；不同時列多個互相競爭的下一步。

新對話處理 `magic-siege` 時，完成平台導讀與 Project 入口導讀後，應先讀 `PROGRESS.md`，再由本文件回到對應里程碑。
