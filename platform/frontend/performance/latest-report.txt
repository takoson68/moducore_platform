Findings:
- Initial load is dominated by a single-bundle strategy: project-b ships 1062.41 kB of JS because vite.config.js enables `inlineDynamicImports` and disables `cssCodeSplit`.
- Module install is not lazy: projects\dineCore\modules\index.js calls `loadModules()` before allowList filtering, so declared modules are imported before visibility gating.
- Container architecture keeps a global route bucket: src\app\container\register.js stores routes on `window.__MODULE_ROUTES__`, which raises reset and cleanup cost.
- State updates are heavy in projects\dineCore\modules\restaurant-map-editor\store.js: 40 full-state spreads and 1 JSON clone calls were detected.
- The store factory does synchronous serialization: src\app\stores\_storeFactory.js writes `JSON.stringify(state)` during set when storage is enabled.
- Legacy vendor assets are still expensive: project-b carries 818.59 kB of non-CSS/JS payload, with project-b bundling html2canvas, Chart.js, fonts, and images together.
- A dead dependency is present: package.json declares `qrcode`, but the source tree has no runtime import for it.
- The largest dineCore module is projects\dineCore\modules\restaurant-map-editor, and its monolithic store shape increases render and memory pressure.
