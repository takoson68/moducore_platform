# Codex 任務：平台核心效能評分（Platform Performance Score）

你現在是資深前端架構工程師，請只針對平台核心進行效能檢測與評分，不要把任何專案內容重量算進平台分數。

## 目標
建立一份「平台核心評分報告」，用來判斷平台架構本身是否健康、可維護、可擴展。

平台核心指：
- container
- module runtime
- router registration mechanism
- store factory
- persistence strategy
- shared app runtime
- project/module boot flow

---

## 強制規則
1. 不可把單一專案頁面內容、圖片、字型、商業模組重量算入平台分數
2. 不可把 project-b、dineCore、flowCenter 的內容型 bundle 當成平台核心失分
3. 若某問題屬於平台共用層，才可列入平台 findings
4. 若某問題只存在某單一專案，必須排除，並註記應交給「專案評分」

---

## 平台評分範圍

### A. Container 邊界與註冊機制（20 分）
檢查：
- 是否使用全域 window bucket
- route/module/service 是否正確收斂於 container
- 是否可 reset / isolate
- 是否存在破壞平台邊界的共享狀態

### B. Module Runtime 載入策略（20 分）
檢查：
- allowList 是否先於 import
- module loader 是否真正 lazy
- boot flow 是否乾淨
- module registration 是否存在不必要 eager install

### C. Store Core 與 Persistence 策略（20 分）
檢查：
- _storeFactory.js 是否同步 stringify / sync storage IO
- 是否支援 persisted subset
- 是否存在高頻更新阻塞風險
- API 是否可維護

### D. Runtime 操作效率（20 分）
請以平台共用層為主，模擬：
- 100 次 module switch
- 1000 次 shared store update
- router setup
- shared runtime boot

### E. Architecture Health（20 分）
檢查：
- container / runtime / store / router 責任是否清楚
- 是否存在過度全域依賴
- 是否存在不利於多專案隔離的設計
- 是否存在未來擴展風險

請輸出：

[Platform Performance Report]

Score: XX / 100

- Container Boundary: XX/20
- Module Runtime: XX/20
- Store Core: XX/20
- Runtime Efficiency: XX/20
- Architecture Health: XX/20

---

Verified Platform Facts:
- 只列平台共用層的事實
- 每一點都要附檔案路徑與原因

---

Excluded Project-Level Issues:
- 列出哪些問題被排除
- 說明為何這些不屬於平台評分

---

Findings:
- 只列平台層問題
- 禁止列入單一專案內容重量

---

Suggestions:
- 只給平台層修正建議
- 必須可直接實作
- 不可空泛

---

Final Verdict:
請明確回答：
1. 平台核心是否健康
2. 平台是否存在架構級風險
3. 平台下一輪最應修的 3 件事

---

## 額外要求
1. 若發現 window.__MODULE_ROUTES__、同步 storage IO、共用 runtime eager 問題，需明確標記
2. 若問題只出現在某專案模組，請排除並歸類為 project-level
3. 報告必須區分：
   - Verified Facts
   - Inferences
   - Suggestions
4. 不可沿用舊報告模板，必須重新依實際程式碼檢查



## 報告產出
