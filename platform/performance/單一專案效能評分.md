# Codex 任務：單一專案效能評分（Project Performance Score）

你現在是資深前端效能工程師，請針對單一專案進行效能檢測與評分。

## 目標
建立一份「專案效能報告」，用來判斷該專案是否正確使用平台、是否存在首屏過重、依賴過肥、頁面切分不良等問題。

---

## 輸入規則
請先要求或讀取一個 targetProject 名稱。
若未指定，預設不執行。
只針對該專案評分，不可混入其他專案平均值。

targetProject 範例：
- dineCore
- flowCenter
- modudesk
- project-a
- project-b

---

## 強制規則
1. 只檢查 targetProject
2. 不可把平台共用層小缺陷當作專案主因，除非它直接影響該專案
3. 專案分數必須反映：
   - bundle size
   - asset size
   - route lazy load
   - page/module loading strategy
   - heavy dependency usage
   - render hotspots

---

## 專案評分範圍

### A. Initial Load（25 分）
檢查：
- JS bundle size
- CSS size
- other assets size
- FCP / LCP / TTI
- 是否有首屏過重問題

### B. Page / Route Splitting（20 分）
檢查：
- route 是否 lazy load
- page 是否仍預先引用重模組
- 是否有 chunk 分割不合理
- heavy feature 是否延後載入

### C. Dependency & Asset Control（20 分）
檢查：
- Chart.js / html2canvas / editor / images / fonts / qrcode 類依賴
- 是否存在 dead dependency
- 是否有大圖未壓縮
- 是否有不必要 preload

### D. State & Rendering Hotspots（20 分）
檢查：
- 大型 store
- full-state spread
- 不必要 re-render
- deep clone / JSON clone
- 高頻更新熱點

### E. Runtime UX Efficiency（15 分）
模擬：
- 100 次 route switch
- 1000 次 store update
- 1000 cards render
- 2000 rows render
- FPS / 記憶體保留量

---

## 輸出格式

請輸出：

[Project Performance Report]

Project: <targetProject>
Score: XX / 100

Breakdown:
- Initial Load: XX/25
- Route Splitting: XX/20
- Dependency & Asset Control: XX/20
- State & Rendering: XX/20
- Runtime UX: XX/15

---

Measured Facts:
- JS / CSS / Other
- Routes
- FCP / LCP / TTI
- Runtime benchmark
- Memory

---

Verified Code Facts:
- 列出 targetProject 實際檔案檢查結果
- 每點都要附檔案路徑

---

Findings:
- 只列 targetProject 的問題
- 要具體到頁面、模組、依賴或 store

---

Suggestions:
- 必須可直接實作
- 先給最穩定方案
- 再補進階方案（選用）

---

Final Verdict:
請明確回答：
1. 此專案目前主要瓶頸是什麼
2. 這些問題屬於平台層還是專案層
3. 該專案下一輪最應修的 3 件事

---

## 額外要求
1. 報告最後附上 Delta 建議格式：
   - Before / After / Delta
2. 若 targetProject 有單一重模組拖累，必須明確點名
3. 若 targetProject 初始載入過重，必須明確區分：
   - JS 過重
   - asset 過重
   - lazy 不足
4. 不可沿用舊報告模板，必須重新檢查 targetProject 實際內容




## 報告產出
- 應產出至本層目錄新增檔案
