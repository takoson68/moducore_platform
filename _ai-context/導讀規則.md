# 導讀規則

## 資訊優先級

發生衝突時依序判斷：

1. `_VibeCore/RootIndex.md` 與 `_VibeCore/world/` 憲法。
2. `_VibeCore/engineering/` 已生效規則與 Contract。
3. 使用者當前明確指令（在以上規則允許的範圍內定義任務目標）。
4. 實際原始碼、設定、測試與命令輸出，用於判斷現況，不得反向降低規則。
5. `_VibeCore/feedback/` 已記錄的問題、討論與假設。
6. `_workspace/CURRENT_WORK.md`。
7. `_workspace/_reports/`、舊存檔與其他歷史資料。

## 憲法一致性檢查

- 工程任務開始前，先依 `_VibeCore/RootIndex.md` 完成 World 主鏈 00–09，再讀取適用的 Engineering Contract 與目標目錄 `index.md`；不得先以程式現況或 Project 文件推導「規則允許什麼」。
- 將適用規則轉成此次任務的檢查點，再檢視實作；既有程式碼、測試通過或歷史決策都不能讓違規實作合法化。
- 修改完成後，再按檢查點核對責任層、Container／Module 註冊、Store／Storage 資料流及 API 邊界；若發現不符合，先修正或依正式回饋規則記錄，不得默默略過。
- 任何對 `_VibeCore/world/` 的變更仍須走 World Change Protocol；本導讀文件只落實閱讀與檢查流程，沒有修改憲法的權限。
- 若 World 入口或導讀鏈出現矛盾、缺漏或無法確認，依 `STARTUP_DECLARATION.md` 停止受影響工作並指出具體衝突，不自行選一份文件覆蓋另一份。

使用者指令不能默認授權破壞性操作；需要刪除、覆蓋、Production 變更或外部發布時，仍應確認範圍與權限。

## 閱讀方式

- 先讀 `_ai-context/index.md` 的初始化必讀。
- 進入 `_VibeCore` 子層前先讀該層 `index.md`。
- 先讀索引與摘要，再依任務讀直接相關文件。
- 初始化不全量讀取歷史報告、舊存檔或所有 Project。
- 使用 `rg` 精準定位，不因檔案存在就全部載入。
- `planned` 是目標，不代表已實作；必須回到程式與驗證結果確認。
- `CURRENT_WORK.md` 若與 Git 或原始碼衝突，以實際狀態為準並更新紀錄。
